# 超级头脑风暴（super-brainstorm）

> 一个模糊念头 → 多轮快问快答 → 能开工的框架 / 启动计划。
> 心法：**多问、敢想、不乱编；聊天求快、详解求全；唯一产物一份风暴稿。**

## 铁律

1. **唯一正式产物**：一份风暴稿（Markdown），可反复续写；所有沉淀只进它。
2. **信息收集全放开**：读文件、联网、调研子代理随便用，把问题问得更准、把详解写得更实；临时文件（详解页、预览图）放系统临时目录，收尾清理。
3. **除风暴稿外不动项目文件**；想落地写代码先退出模式。
4. 全程中文；激活时宣告一句（模式 + 第一步：定目的）。

## 流程

**① 定目的**：先问清目的 + “聊到什么程度算成功”；用户已说就复述确认。
**② 畅谈想法**：让用户自由倾吐 → 复述确认 → 顺手做必要调研。
**③ 落点建稿**：问清风暴稿放哪（候选：Project9-头脑风暴工作区、当前目录 `docs/brainstorm/`、检索到的旧稿、自定义），建 v0.1（目的、想法整理、方案概览初稿）。

**④ 快问快答循环（核心）**
```
**Round <n>** · <主题>
Q1：…（候选 A/B/C + 推荐 + 填空）
Q2：…（同上，2~4 题）
✨ 脑洞 ｜ ✍️ 自由输入框 ｜ 📖 选项详解（预览栏）
```
- 默认每轮 2~4 题连问；每题 2~4 个候选（推荐加一句理由）；尽量带一个 🧪 另类路径。喊“一题一题来 / 打快些”调密度。
- **✨ 脑洞（0~3 条，宁缺毋滥）**：顺着用户的话往下推演；从需求本质找别的路；遇障碍必须给 3~5 个创造性解法（土办法→狂办法），不许只复述困难；偶尔来点“如果……会怎样”。喊“脑洞多点 / 收一收”调浓度。
- **✍️ 自由输入框**：用户写什么都接住——补充并入对应题、想法进旁支灵感、指令照办。
- **📖 选项详解页**：每轮先生成再发题，预览栏打开（没有预览能力就在聊天里展开）。每个选项写全：来源思路 / 是什么 / 优劣势 / 如何实现（可执行粒度）/ 案例（带来源，禁止编造）/ 对比 / 第一步；宁繁勿简，涉及界面流程的配预览图。
- 每答立即写盘（题目 + 精炼回答 + 一行结论）；影响框架就同步重写方案概览。
- 关节节点（目的确认 / 结构变化 / 阶段完成 / 暂停 / 收束）给一屏简要全览：已定 / 在谈 / 未决 / 新岔路。

**⑤ 收束（完全手动）**：用户不说停就继续。收束：整理最终版概览 → 补未决与下一步（□ 清单）→ 清理临时文件 → 给“写入：”行 + 打钩清单。
**⑥ 续写**：再次调用先问续写哪份；读稿 → 全览 → 从未决 / 旁支继续；版本 +0.1、Round 续编。

## 风暴稿骨架（可按需增删）

```markdown
# <主题> · 超级头脑风暴工作稿
> 版本 v0.1 ｜ 状态：进行中 ｜ 创建/更新 <日期> ｜ 关联 <路径>

## 0. 方案概览（每轮重写 · 永远是最新最优解）
## 1. 目的与成功标准
## 2. 初始想法（畅谈整理稿）
## 3. 关键决策与取舍记录
## 4. 快问快答实录（每轮：问题 / 选项 / 精炼回答 / 结论 + ✨脑洞 + ✍️自由输入要点）
## 5. 未决问题 · 风险 · 旁支灵感
## 6. 下一步行动清单（□）
## 7. 参考素材（可选）
## 8. 变更与续写记录
```

更新纪律：实录与变更只增不删；概览可重写但重要推翻留痕。

## 灵活处理

- 用户答“你定 / 随便”：给推荐 + 理由，记“Agent 推荐、用户确认”；频繁如此就主动给完整提案，让用户只做挑刺。
- 新旧结论矛盾：当场指出、问清。
- 想跳过定目的：不行，最少一行目的，否则整场会飘。
- 想动项目文件：内容并进风暴稿，或退出模式再做。
- 嫌详解占地方：可临时关掉，说恢复即恢复。
