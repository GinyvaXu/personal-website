# 组会脑暴（group-meeting-brainstorm）

> 不是让一个模型换六种语气，是让六个**互相看不见、各有私心、各有盲区**的人，在一张桌子上把事吵清楚。
> 心法：**先写后说、先散后收、分歧留档、结论有主。**

---

## 1. 什么时候用

**适合**

- 产品 / 项目 / 组织 / 内容等复杂问题，需要真实分歧，不是要一个“正确答案”。
- 用户想参与讨论，且愿意看角色之间的冲突、妥协和收束。
- 需要产出决策日志、认领表、开发草案、逻辑架构图等可执行产物。
- 话题有多个专业视角，单模型容易“什么都说得通”。

**不适合**

- 纯事实问答、紧急决策、只需一个方案。
- 没有分歧空间的话题（例如“帮我改个错别字”）。
- 用户只想快速拿答案；用 `super-brainstorm` 的快问快答更合适。

**和 super-brainstorm 的区别**

| | super-brainstorm | 组会脑暴 |
|---|---|---|
| 形式 | 多轮快问快答 + 选项 | 模拟真组会 + 角色对话 |
| 角色 | 一个主持人 | 5~6 个独立子智能体 |
| 重点 | 快速收敛 | 真实分歧、责任、授权 |
| 产物 | 风暴稿 | 风暴稿 + 决策日志 + 认领表 + 可选草案/图 |

---

## 2. 八个核心机制

1. **独立子智能体**：每个角色单独生成，互不可见；避免一个人换声线。
2. **私有信息**：每人只拿一部分事实；会上互相追问，才拼出全貌。
3. **私心与盲区**：每个角色有代价、有偏见；反对有结构性原因，不是为演而演。
4. **会前便签**：先写后说，避免第一个发言的人锚定全场。
5. **窄任务 + 配额**：外部视角只做一件事，有字数/句数上限；跑题进停车场。
6. **白板 + 分歧账本**：共识 / 分歧 / 停车场 / 认领表；不强行共识。
7. **结论有主 + 授权**：每条结论要有责任人、交付物、日期、授权人；没有授权，认领只是签字。
8. **拒绝权**：任何人可以无理由拒绝；拒绝是数据，不是失败。

> 第 7、8 条是这套方法最容易被忽略、也最值钱的地方：**会议不是让人答应，是让事真的发生。**

---

## 3. 角色配置

### 3.1 六个生态位

| 生态位 | 他负责 | 典型口头禅 |
|---|---|---|
| **收敛者** | 砍、收、问“下周谁做” | “所以下周谁做？” |
| **失败模式专家** | 成本、边界、出事谁担 | “先说你打算怎么失败。” |
| **人的代言人** | 一手证据、情绪、沉默的人 | “我上周听到一个用户说……” |
| **跳跃者** | 极端版本、比喻、反常识 | “如果把它反过来呢？” |
| **度量者** | 可观测结果、反作弊、止损 | “留存呢？” |
| **外部观察员** | 只观察会议本身，不给方案 | “你们刚才那个动作……” |

- 5~6 人；奇数优先，避免平票。
- 外部观察员只在“需要看会议本身”时加；他的窄任务必须写死（例如每轮 ≤3 句、只描述不建议）。
- 名字可以是真名、化名、动漫人物；**壳不重要，私心、盲区、私有信息才是核**。

### 3.2 角色卡模板

| 字段 | 填写要求 |
|---|---|
| 姓名 / 出处 | 真名、化名或虚构人物；出处只做语气参考 |
| 专业视角 | 他在哪个领域有判断力 |
| 性格 / 说话方式 | 3 个形容词 + 一句口头禅 |
| 私心 | 他在这场会里想得到什么（预算 / 声誉 / 不被砍 / 证明自己） |
| 盲区 | 他系统性看不见什么 |
| 窄任务 | 每轮只做一件事，写死 |
| 私有信息 | 只有他知道的一个具体事实（数字 / 原话 / 案例） |
| 发言配额 | 每轮字数或句数上限 |

### 3.3 怎么选角色

- 先问：这个决定真正需要哪 4~5 个视角？不要凑人头。
- 每个角色必须能改变结论；如果删掉他，讨论没变化，就删掉。
- 两个角色不要同一生态位；宁少一个，不要两个“产品负责人”。
- 外部人只带一个窄任务；不要给他自由发言权。

## 4. 会前

### 4.1 定目的

先写清：

- **目的**：这场会要决定什么？
- **成功标准**：聊到什么程度算成功？
- **不做什么**：哪些不在本次范围？
- **产物**：风暴稿 / 决策日志 / 开发草案 / 架构图？

### 4.2 写私有信息

给每个角色一条**只有他知道**的事实：

- 一个数字（“14 场会 63 个想法，2 个进排期”）
- 一句原话（“我不是没想法，我是在等谁先安全地开口”）
- 一个失败案例（“40 万工作坊，三个月后便利贴还在墙上”）
- 一个现场观察（“老板迟到 20 分钟，那 20 分钟里团队说的话比之后 2 小时都多”）

私有信息要能**改变讨论**，不是背景装饰。

### 4.3 独立便签

每个角色由独立子智能体生成一张便签，互不可见：

```
你在扮演【角色】。会议题目：【题目】。
你的私有信息：【只有你知道的事实】。
写一张会前便签：
【判断】我认为这件事最大的问题是什么（1-2 句）
【我带来的事实】一件只有你知道、能改变讨论的事实（2-4 句，具体）
【必须写进 v1 的一条规则】一条具体、可执行的规则（1 句）
≤250 字；不要看别人的便签；不要调用工具；只输出正文。
```

### 4.4 建风暴稿

`YYYY.M.D-<主题>.md`，至少包含：

- 目的与成功标准
- 角色卡
- 会议规则与议程
- 会前便签（原文）
- 会议实录
- 白板 / 分歧账本
- 下一步

---

## 5. 会议流程（55 分钟）

| 时间 | 环节 | 产出 |
|---|---|---|
| 0-5 | 开场：规则、停车场、角色 | 停车场空表 |
| 5-20 | 诊断：只发散，不评判 | 3 个诊断候选 + 核心张力 |
| 20-40 | 设计：缺口 → 认领 → 授权 | 三张单 |
| 40-52 | 压测：每人一个崩法 + 补丁 | 失败模式表 |
| 52-55 | 收束：每条想法有去向 | 认领 / 停车场 / 墓碑 |

### 5.1 主持人规则

- 只掌流程，不替角色发言；不评价想法，只归类。
- 第一轮只发散；红队放在发散之后。
- 每人每轮有字数/句数上限；跑题进停车场。
- 分歧必须显式登记，不允许“大家都没意见”糊过去。
- 用户可随时 @ 角色、叫停、加人、换题。

### 5.2 每轮的动作

1. **独立写**：每个角色先写，不互相看。
2. **上墙**：主持人只归类，不评价。
3. **交叉质询**：每人可向另一人提一个“你必须回答”的问题。
4. **白板更新**：共识 / 分歧 / 停车场 / 认领。
5. **暂停**：给用户一屏全览，等用户插话或继续。

## 6. Prompt 模板

### 6.1 诊断轮

```
本轮只诊断，不给完整方案。用你的角色视角，指出：
1. 【思考】2-3 条，短句，像心里快速闪过的判断。
2. 【发言】2-4 句，角色语气；只诊断，不给方案。
3. 【我要问用户的一个问题】1 句，具体、能改变下一步。
≤260 字；第一人称；不要调用工具；只输出正文。
```

### 6.2 设计轮

```
用户已拍板：【决策】。
给一个具体机制，不要讲原则。四段：
1. 【机制名】一句话
2. 【怎么跑】3-5 步，具体到谁在什么时候做什么
3. 【我最不能接受】对方阵营哪一点，为什么
4. 【防权力绕过】这个机制怎么防止“因为他是老板/老人/声音大”就失效
≤320 字；第一人称；只输出正文。
```

### 6.3 压测轮

```
给一个具体的崩法（不要“大家不配合”这种废话），一个早期信号，一个补丁。四段：
1. 【崩法】谁在什么时候做了什么，导致什么后果
2. 【早期信号】会上/会后能看到的一个迹象
3. 【补丁】改哪条规则，怎么改
4. 【我不接受的补丁】别人可能提的哪种修法，你觉得是止痛药不是解药
≤260 字；第一人称；只输出正文。
```

### 6.4 外部观察员

```
只写一条现场观察，≤3 句：这轮讨论暴露了什么他们自己没说的话？
只描述，不给建议；第一人称；只输出正文。
```

### 6.5 收束

```
把三轮收成：已定 / 默认 / 未决 / 停车场 / 认领 / 下一步。
不要新增未讨论的事实；有矛盾当场指出；每条结论要有责任人、交付物、日期、授权人。
```

## 7. 白板与收束四件套

### 7.1 四个 Tab

- **共识**：已经同意的。
- **分歧**：还没解决的；不强行共识。
- **停车场**：跑题但不想丢的。
- **认领表**：谁做什么、什么时候、谁授权。

### 7.2 认领表

| 列 | 要求 |
|---|---|
| 名字 | 具体的人，不是“大家” |
| 交付物 | 看得见的东西 |
| 48h 可验收物 | 某时、某人看到某个东西 |
| 复查日 | 具体日期 |
| 授权人 + 权限 + 资源 + 上限 + 兜底人 | 没有授权，认领只是签字 |
| 难度 | 要不要钱 / 跨部门 / 否掉人 |

### 7.3 三个上限

- 每场最多放行 3 条认领。
- 高权力者每场最多认领 1 条。
- 每场至少 1 条“硬想法”：被认领，或由说“给不起”的人署名判死。

### 7.4 一个在场

- 授权人必须在场，能说出资源口袋和到账日。
- 不在场 = 只能认领“探索”，不能认领“交付”。

### 7.5 反过度承诺

- 任何人可无理由拒绝；拒绝不进档案，只记缺口信号。
- 授权人承诺的资源没到账 → 标红授权人，不标红认领人。
- 散会前匿名收“答应了但心里没底”的卡，只统计，不点名。
- 第 7 天报三个数：认领率、硬想法认领率、拒绝率。

> 一个真实教训：五种崩法里没有一次是有人拒绝，全都是有人答应了。**最危险的失败不是没人说话，是所有人都答应了。**

## 8. 收束与产物

### 8.1 收束清单

- 最终版方案概览（一页）
- 决策日志：已定 / 默认 / 未决
- 认领表：人 + 交付物 + 日期 + 授权人
- 停车场
- 下一步（□ 清单）
- 用户确认（不要替用户宣布共识）

### 8.2 可选产物

| 产物 | 说明 |
|---|---|
| **风暴稿** | 会议全过程，只增不删 |
| **开发草案** | 面向开发：定位、范围、流程、页面、数据、技术、排期、验收 |
| **逻辑架构图** | 用 Archify `tree` 做思维导图；`architecture` 做组件图；`lifecycle` 做状态机 |
| **只读会桌屏** | HTML + SSE：角色思考气泡、台词、白板、轮到你提示；用户在聊天里输入，网页只读显示 |

## 9. 失败模式与修复

| 崩法 | 早期信号 | 补丁 |
|---|---|---|
| 六个角色一个声音 | 句子长度、逻辑、态度都差不多 | 每人一条私有事实 + 一个私心 + 一个盲区 |
| 会变成表演 | 热闹，但散会没人认领 | 认领表 + 授权人 + 复查日 |
| 主持人变成主角 | 主持人开始给方案 | 只掌流程；用户可 @ 角色 |
| 流程压死想法 | 一袋外卖要五个人投票 | 分诊：小案轻流程，大案才上公判 |
| 所有人同意 | 没人拒绝、没人提反例 | 拒绝权 + 外部观察员 + 分歧账本 |
| 成本太高 | 18 次子智能体调用 | 5 人、3 轮、并行、合并观察员 |
| 角色串味 | 每个角色都像全知全能 | 只给角色卡 + 私有信息，不给全量会议记录 |

---

## 10. 成本与节奏

- 6 人 × 3 轮 ≈ 18 次子智能体调用；5 人 × 3 轮 ≈ 15 次。
- 独立调用并行；只有外部观察员需要等一轮结束。
- 55 分钟是“会议内时间”，不是真实等待时间；真实取决于模型速度。
- 嫌重：5 人、2 轮（诊断 + 设计）、观察员后置；或先跑“轻版”30 分钟。

## 11. 示例：校园帮帮

- 6 个角色：产品、架构、用户研究、创意、增长、外部观察员。
- 3 轮：诊断（谁帮谁、为什么帮、凭什么信）→ 设计（人情点 / 信誉分 / 分楼 / 邀请）→ 压测（表满权空、公判变网暴、邀请变拉人头）。
- 产出：开发草案 v1.0（21 节）+ Archify 逻辑架构图（60 节点）。
- 关键结论：
  - 人情点不是货币，是欠条；信誉分不是钱包，是履约记录。
  - 小案调解（≤30 点），大案公判（>30 点或安全/隐私）。
  - 先赔后查；无责平台出；不罚款、不示众。
  - 授权人必须在场；不在场只能“探索”，不能“交付”。
  - 邀请是“递钥匙 / 点灯”，不是拉人头；激励不进信誉分。
